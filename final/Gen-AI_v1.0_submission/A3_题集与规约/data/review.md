# 题集与规约双人评审记录（v1.7，2026-11-05）

本文件是 D1.5 的交付物：记录 34 道题在冻结前后的评审过程、发现的问题与闭环结果。
评审不是走过场——下面第 2 节列的 14 条问题里有 9 条会直接让下游返工（规约与题面矛盾、
急停语义写反、条款恒假），必须留下记录。报告第 2 章（数据质量）与第 4 章（失败归因）
要引用本文件。

> v1.7 增补说明：R7—R14 来自成员 4 的 `tests/ambiguities.md`「需要成员1 回答的阻塞项」
> 与成员 3 的 `判据待核查.md`，逐条对照题库原文核实后修订。修订只动**派生字段**
> （约束 K 的措辞、LTL 条款、说明），**不动英文需求原文、不动 I/O 变量名**，
> 因此 136 条正式实验记录的输入输出完全可比，只是判定口径变准了。

## 1　评审机制

| 项 | 约定 |
| --- | --- |
| 评审人 | 第一评审：成员 1（出题人自检）；第二评审：成员 4（用例作者，站在"能不能判对错"的角度） |
| 时机 | D2 24:00 前完成，D3 10:00 冻结前闭环；v1.7 的二次评审判定发生在 11-05（上传 GitHub 前） |
| 粒度 | 逐题四类检查：① 字段完整性与类型；② 需求与 I/O 表自洽（每个约束都能落到点名信号上）；③ 规约与约束的映射（K 编号对得上、条款可判定）；④ 错误示例是否真能被用例抓出来 |
| 异议处理 | 评审人写"接受 / 驳回 + 理由"，出题人 24 小时内改完或给出反驳；未闭环的题不得进冻结包 |
| 工具 | `python tools/schema_check.py`（字段、I/O、K 映射、来源表）、`python tools/ltl_check.py`（语法与命题可溯源） |
| 记录 | 本文件；改题必须同时改 `data/CHANGELOG.md` 的条目 |
