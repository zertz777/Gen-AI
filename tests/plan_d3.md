### 1.3 执行与计分

```bash
# 每个变异体：打补丁 → 编译 → 跑该题全部用例
python tests/run_tests.py --cases tests/cases/P03.csv \
  --io tests/cases/_fixtures/P03.io.json \
  --out verify/mutants/M-P03-1/result.jsonl \
  --backend replay --actual verify/mutants/M-P03-1/test/actual
```

- **killed**：该题任一用例 `fail`（首失配拍要记下来，和 1.2 的“预期杀手”对照）；
- **survived**：全部 `pass` → 说明用例强度不够，补用例后重跑；
- **invalid**：编译不过或超时 → 不计入分母，换一个变异体；
- 变异得分 = killed / 30，按题报告（每题 5 个）。

产物：`verify/mutants/<变异体ID>/`（`final.st`、编译日志、`result.jsonl`、`mutation.json`）。
最后在 `tests/report.md` 第 6 节点名**用例最弱的三道题**（存活最多的），并说明补了哪几条用例。

### 2.2 口径

- 单条属性超时 **300 s**；超时记 `timeout`，**不算违反**；
- 结果四态：`pass / violated / timeout / skipped`（`skipped` = 该属性当前后端不可表达，如 REAL 浮点比较）；
- 至少留 **1 条可读反例**：能对上具体周期与变量，存 `verify/plcverif/<题号>/counterexample.txt`；
- 浮点属性（P03 的 REAL 比较）在 CBMC 上不可判定时，先把量纲放大成整数再建模；仍不行就标 `skipped` 并写明原因。
