## 3 执行链路

```
cases/<题号>.csv ─┐
_fixtures/*.io.json ─┼→ case_loader（校验列名/类型/拍号）
                     ├→ 执行通道（本批次：实验机 CODESYS 逐拍采集）
                     ├→ compare（首个失配拍 + 变量 + 期望/实际）
                     ├→ verdict（pass/fail/timeout/error）
                     └→ evaluation.json → 统计输出/*.csv → 本报告
```

本批次实际使用的测试入口是实验机上的 `agent/scripts/member4_test.py`
（配置见 `配置/member4.codesys.yaml` 的 `tools.test`：CODESYS V3.5 SP22 Patch 4，
`evidence_kind = live`）。它按本目录的用例与 fixture 逐拍比对，结果写进 `evaluation.json`：

```json
"test": {"status": "fail", "total": 9, "passed": 4,
         "failures": [{"case_id": "P19-02", "cycle": 8, "signal": "MoveUp",
                        "expected": true, "actual": false}]}
```

关键约束（D2-4 定，未变）：actual 列名必须与 fixture 的 OUT 列逐字一致；缺列判 `error` 而不是 `fail`；
同一程序、同一 seed 跑两次结论必须一致。

## 5 失败分布与复现

| 项 | 数值 |
| --- | --- |
| 缺陷条数（一条失配 = 一条） | **316** |
| 涉及 run | 75 |
| 按组 | E1 42、E2 56、E3 103、E4 115 |
| 按原因 | 逻辑 182（57.6%）、时序 64（20.3%）、边界 61（19.3%）、工具超时 9（2.8%） |

完整明细见 `tests/defects.md`（316 行，含 `run_id / case_id / 拍号 / 变量 / 期望 / 实际 / 复现`）。
`kind` 的判定规则写死在生成脚本里，可复现：编译失败 → 编译；超时 → 工具超时；边界类用例 → 边界；
`spec_refs` 命中的 K 条款含时间语义 → 时序；其余 → 逻辑。

### 5.1 三个典型失败

**安全类 · `E3_P13_1_42` / P13-05 第 1 拍**
`TEMP_SETPOINT_ADJUST` 期望 3、实际 0。用例验证"模式切换当拍修正立即跟随；切到夜间中断计时，
风机不得启动"。程序在切换拍没有立即更新修正值，属于**时序响应滞后一拍**。

**异常类 · `E3_P17_1_42` / P17-01 第 1 拍**
`recipeQueryResult` 期望 `{recipeID:1, ingredientType:10, ingredientRatio:0.5, productionTemperature:100.0}`，
实际整结构为 0。这是**整题 0/8** 的典型：程序没有把 `VAR_IN_OUT` 的配方结构写出去，
不是某个边界算错，而是接口级没接上——这类失败在缺陷单里一眼就能区分。

**边界类 · `E3_P17_1_42` / P17-08 第 1 拍**
`recipeAdded` 期望 TRUE、实际 FALSE。用例场景是"库里只剩 1 个空位时新增应成功"，
程序在临界容量上判错，典型的**边界条件 `>=` 写成 `>`**。

## 6 回归（不可得，如实标注）

| 项 | 数值 |
| --- | --- |
| 复测题数 | 不可得 |
| 修好 | 不可得 |
| 仍失败 | 不可得 |
| **修复引入的破坏数** | 不可得 |

原因：算"修 A 把 B 改坏"要求同一题有**修复前后两份逐拍 actual**。精简包只保留每次 run 的最终产物，
`repair_1.evaluation.json` 在整个包里只出现 1 次，无法配对。要补这一节，需在实验机对
`repair_rounds > 0` 的题重跑并保留两次 actual。**不拿替代数据凑这一列**，否则整张回归表失去意义。

## 7 已知局限

1. **`X` 拍不判定**：输出格中 `X` 占 **0.62%**（565 / 91 541），这些格上的错误测不出来；
   输入列不允许 `X`（loader 直接拒），见 `ambiguities.md` A-01…A-46。
2. **期望值来源**：按题面 K 约束手推，不是从被测程序反推；但没有独立参考实现做交叉验证，
   "用例本身写错"只能靠人工复核——D3 复核出的 33 条争议正是这类（见 §7.5）。
3. **题量口径**：按 34 题（成员1 v1.6）执行，主轮 136 跑；任务书排期写的 32 题/128+48 已作废，
   报告里的分母一律用 34/136。
4. **`S05` 溢出边界不可达**：K3 的 1 000 000 L 需要 2×10⁶ 个脉冲，接口无法注入初值，
   `S05-06` 只覆盖"清零与脉冲同拍"的边界，溢出本身未测。
5. **用例版本差异**：实验批次有 5 题（P01、P08、P17、P18、P19）用的是与冻结版不一致的副本，
   其中 P19 的急停极性相反。逐条仲裁与影响评估见 `docs/判据与用例版本核对.md`；
   争议条目共 33 条，已在 `defects.md` §5 单列，**不混进模型失败计数**。
6. **actual 未随包交付**：精简包只给 `evaluation.json`，没有 `test/actual/*.csv`，
   所以本机只能用 replay 以外的通道复跑；缺陷的"复现"命令指向实验机。
7. **工具故障与模型失败分离**：`timeout` / `error` / `missing` 均不计入模型失败；
   本批次 `工具超时` 9 条、`编译失败` 2 条均已单列。
